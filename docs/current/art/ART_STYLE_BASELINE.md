# 《余烬潮汐》最终美术风格基线

> **决议日期**：2026-09-06
> **决议人**：项目主理人（用户）
> **决议**：C01 当前栅格像素风格正式定版；C02 及后续所有关卡必须以此为统一基准。
> **基准样板**：C01「离港火线」完整玩家流程。
> **资产成熟度**：只以根目录 `ART_ASSET_REGISTRY.csv` 为准；风格定版不等于整个项目达到 Shipping。

## 1. 权威范围

本文是项目唯一的**视觉风格权威文档**，适用于：

- Title、Slot、Campaign、Briefing、Battle、Result 等产品流程界面；
- C01–C14 以及后续新增关卡；
- 地形、道路、港岸、塔、敌人、英雄、舰船、Boss、战斗 FX 与 UI 图标；
- 外购/开源资产筛选、项目原创资产生产和派生调色。

发生冲突时，优先级为：

1. `docs/current/product/PRD.md` 的产品与玩法约束；
2. 本文的视觉语言与制作约束；
3. `docs/current/art/ASSET_CATALOG.md` 的来源与许可证政策；
4. `docs/current/art/ART_PRODUCTION_PLAN.md` 的生产与验收流程；
5. 历史 M4 规范、旧 Style Bible、研究稿与阶段记录。

任何偏离本基线的视觉方案，必须重新取得项目主理人明确批准。

## 2. 核心视觉语言

### 2.1 一句话定义

**正交俯视的海防像素画：冷青灰暮潮世界 + 暖珊瑚港灯与己方单位，以清晰栅格精灵承载主体，程序绘制只服务于光、雾、状态和反馈。**

### 2.2 C01 样板特征

- 真实可辨认的像素灯塔、舰船、礁岸、码头、敌人与防御塔；
- 不是由圆、线、多边形临时拼出的抽象 SVG 感主体；
- 轮廓硬朗、材质有像素细节，但在 `640×360` 忙碌战斗中仍能迅速识别；
- 画面具有“最后港灯守护迁徙舰队”的叙事焦点；
- 暖色代表守护、港灯、舰队和可操作目标，冷色代表海潮、敌群与危险环境。

## 3. 技术规格

| 项目 | 锁定规则 |
|---|---|
| 基准画布 | `640×360` |
| 视角 | 正交俯视；流程背景可使用低角度海报式远景，但像素语言必须一致 |
| 逻辑网格 | `32×32`；不得因美术替换修改路线、BuildNode 或碰撞数据 |
| 单位显示占地 | 普通单位约 32–64 px；塔可使用 64–96 px 源帧；Boss 可更大 |
| 过滤 | Godot `CanvasItem.TEXTURE_FILTER_NEAREST` |
| 缩放 | 最近邻；避免非必要的非整数放大；禁止线性模糊 |
| 描边 | 1–2 px 深色外轮廓，重点对象必须与背景分离 |
| 动画 | 像素逐帧；移动方向、攻击、受击、死亡状态需保持轮廓稳定 |
| 合成 | 栅格主体 + 少量程序化雾、暗角、辉光、状态条、选择范围、路径激活微光 |

## 4. 色彩与材质

### 4.1 主色角色

- **炭黑/深海墨色**：轮廓、前景礁石、阴影和界面底板；
- **冷青灰/灰绿**：海面、潮湿石材、敌人主体与暮潮环境；
- **羊皮白**：主文字、航图刻度、浪花与高光；
- **暖珊瑚/余烬橙**：灯塔光源、己方塔、舰队识别、CTA、告警重点；
- **低饱和铜木色**：船体、码头、岸防器械和旧港设施。

### 4.2 配色规则

- 高饱和暖色面积必须小，只用于焦点和状态；
- 敌群即使使用青色高光，也必须保留深色主体和可读轮廓；
- 同一关卡可以改变天气、时间与局部主题色，但不能改变暖己方/冷威胁的识别关系；
- 后续章节允许新增芦苇绿、雾紫、冰蓝等章节色，但必须压入上述主色体系。

## 5. 世界与关卡构图

- 地图主体必须由像素地形、建筑、道具和贴图组成；不能让调试线框或几何占位成为最终画面主体。
- 路线应读作世界中的栈桥、堤岸、潮道、礁缝或道路，不画成脱离环境的流程图。
- BuildNode 必须清晰，但应像岸防基座、锚点或机械底座，而不是纯 UI 圆点。
- 每关必须有一个可复述的视觉地标，例如灯塔、潮门、沉船、沼冠或雾塔。
- 战场背景不能抢过塔、敌人与路线；细节密度在可建区和交战区附近适当降低。
- Title、Campaign、Briefing 与 Result 应复用关卡地标和资产家族，避免“菜单一套风格、战斗另一套风格”。

## 6. 塔、敌人与角色

### 6.1 防御塔

- 塔基、武器头和攻击方向必须一眼可辨；
- 己方塔保留暖珊瑚、黄铜或灯火高光；
- 升级应增加结构、灯点或武器细节，不能只改颜色；
- 攻击动画必须有机械后座、蓄力、喷发或脉冲等明确动作。

### 6.2 敌人

- 敌人以物种/功能轮廓区分，不能只靠色相；
- 群体单位可由多个错位小体组成，但逻辑生命条仍保持单一清晰归属；
- 护甲、治疗、隐匿、飞行、Boss 阶段等功能需要像素主体变化或明显状态附件；
- 冷青高光用于敌潮统一性，不得让所有敌人变成同一团荧光噪点。

### 6.3 英雄与舰队

- 英雄必须比普通敌人拥有更稳定的面部/装备识别和暖色友军标记；
- 舰队是本项目叙事主体，不作为随意的背景剪影处理；
- 舰船比例、木材色和灯火色应与 C01 Scallywag 派生舰船保持同族感。

## 7. UI 与产品表现

- UI 继续使用 Ark Pixel CJK 字体和硬边像素布局；
- 主操作使用暖珊瑚，次操作使用低对比深色；同屏只保留一个最强 CTA；
- 面板允许半透明炭黑底，但禁止玻璃拟态、柔和渐变卡片和默认 Godot 主题感；
- Campaign 地点按钮附着于真实港区/关卡地标，不再用抽象节点流程图主导画面；
- Result 使用世界状态表达胜负：灯塔亮/灭、舰队通过/受阻，而不只是一张统计弹窗。

## 8. 允许与禁止

### 允许

- 使用与 C01 同视角、同像素密度和同轮廓语言的 CC0/自有像素资产；
- 对来源资产进行确定性裁帧、重组、调色、尺寸适配和图集整理；
- 用程序绘制雾、潮汐 tint、暗角、攻击闪光、状态环和可访问性反馈；
- 每关在统一语言内设计独特地标、敌种和环境主题。

### 禁止

- 用基础圆形、线条、多边形拼出最终塔、敌人、舰船或建筑；
- 混入平滑矢量、3D 渲染、手绘厚涂、明亮卡通或等距素材；
- 线性缩放导致像素模糊；
- 直接搬入未经统一调色、像素尺度与轮廓检查的素材包；
- 为适配美术修改战斗数据、路线几何、波次、伤害或模拟生命周期；
- 在未重新批准的情况下为后续关卡另起一套 UI 或角色画风。

## 9. 后续关卡生产模板

每个新关卡按以下顺序制作：

1. 定义关卡地标、天气、章节辅色与叙事焦点；
2. 选择或绘制符合本基线的栅格来源；
3. 通过可复现脚本完成裁帧、图集、统一调色和 SHA-256 清单；
4. 使用集中式 sprite library 接入运行时，模拟数据保持独立；
5. 生成 Title/Campaign/Briefing（如适用）、Battle Early、Battle Busy、Result 证据；
6. 检查敌塔可读性、像素过滤、路线识别、色觉预设、UI 缩放与性能；
7. 更新 `ASSET_LICENSE_LEDGER.csv`、`ART_ASSET_REGISTRY.csv` 和 `docs/current/art/CREDITS.md`；
8. 未取得项目主理人批准前，不改变本基线。
